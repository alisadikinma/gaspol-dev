## Design

Port superpowers v6's `subagent-driven-development` review discipline into `gaspol-parallel`
(gaspol's SDD analogue). gaspol-parallel already has fresh-subagent-per-task + two-stage
review + 3-attempt escalation. Four gaps to close:

1. **Status protocol** — the implementer's terminal status is implicit ("it reported
   completion"). Make it explicit: `DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` /
   `BLOCKED`. Orchestrator handles each distinctly (NEEDS_CONTEXT → provide + re-dispatch;
   BLOCKED → assess, never blind-retry the same model).
2. **`review-package` script** — a deterministic `review-package BASE HEAD` that writes the
   task's diff to a file and prints the path, so the reviewer subagent reads a stable
   artifact instead of re-running git. Encodes the superpowers gotcha: **BASE is the commit
   recorded before dispatch, NEVER `HEAD~1`** (drops all but the last commit of a multi-commit
   task).
3. **Per-task model dispatch** — make "always specify model explicitly per task" a rule,
   scaled by task class (mechanical→cheap, integration→standard, architecture/review→capable),
   citing the existing `docs/rubric-model-switching.md`. Principle: "turn count beats token price."
4. **fix → re-review loop** — on Critical/Important review findings, dispatch a fix subagent
   then RE-RUN the review (loop until clean), not "fix yourself and move on."
